UX鳥心得—開始UX之旅的行前準備

正式上路前你需要先知道目的地，啾~

Ossian Lin Published on Feb 2020

前言

User Experience，簡稱 UX，翻成中文個人比較常用使用者體驗稱呼。

什麼是使用者體驗？

這看似抽象的概念但實際上就是個流程，並且與我們生活中大小事息息相關。

那麼，UX 到底在做些什麼？

UX 設計的目標是「讓使用者有效的工作」，然而並非只有設計體驗的過程；因此在接下來的系列文章中會慢慢介紹 UX 這職稱，以及做些什麼。

當然各方高手輩出，若有不及之處，或是有誤都歡迎給予賜正。

首先，「UX 是一種流程。」

對，它是一種流程、而非一項事件或任務。

「咦？使用者的體驗不是『使用或工作期間的』體驗嗎？」

這句話可能只對 1/3 或是更少。

每件事都有一個流程，就像你從網路購物、到貨這段期間都是流程，而且當你選擇在這個網站下單開始，以及售後客服等都還在範圍內。

缺乏 UX 流程，就會有不良的 UX。

「欸等等等，你這樣講的咬文嚼字、又 UX 來 UX 去的，很難懂你的意思。」

簡單舉個例子：

你要寫文章/論文之類的，開始前總會先去認識、瞭解要寫的東西是什麼，接著收集資料、做研究，然後實驗、產生文章。

喔～別忘了口試/報告，或是得到的評語。

整個流程就像是使用者操作一項產品，UX 設計師的流程從收集需要的資訊、研究使用者、確保解決方案正確實作，到最後量測結果。因此 UX 設計師是被包含在整個案子流程中，伴隨著工程師、PM、其他設計師等各領域專業人士。

「喔？聽起來我也可以當 UX 設計師啊！」

只要有心，人人都(ry

當然，想要魚與熊掌兼得、同時做好兩件事，就我個人來說是辦不到的。呵。

雖然說「即便是操作起來一肚子火，再爛的體驗也是操作體驗」，但如果公司的流程迫使你做不好的工作，那個流程可能也不適合 UX。記得：總是能夠將流程持續改善。

喔，對了！如果修正流程還是有問題，那可能不出在於流程。

UX 是一連串的流程，而非單一事件或任務。

設計「體驗」流程的基本要點

這段先簡單引出 UX 五大成份，部分會在後續文章搭配個人經驗介紹。

1/心理學 (Psychology)

人是有情感請的，而每個人的心理情感是複雜的；從動機、感覺、回饋、習慣、慾望、需求…等去瞭解使用者，因此在設計時試著盡量忽略自己的情感。

2/可用性 (Usability)

心理為下意識的、可用性為有意識的。

設計上是否過於簡便、防呆機制、使用者與設計師思維是否思維同步率100%、符合或是違反使用者假設、設計是否有邏輯或直覺…等，有些或許可以設計得很困難但帶有點趣味性，例如遊戲，而許多時候不論是誰，都希望能容易簡單。

關於可用性會在後續文章再談。

3/設計 (Design)

UX 設計出來的東西不一定都具有藝術性，看到產品的第一印象、UI，視覺上的呈現著重於「他是怎麼運作的」、「使用者是否反射性的操作」、「設計師想要使用者知道的訊息是否傳遞」等，能有充分的解釋來證明為什麼是 UX 設計師所產出的成果。

4/文字撰寫 (Copywriting)

不同於品牌文案等其他文案有特定目標，或是對公司有所需求，在 UX 文案撰寫上比較直接，且能夠簡單的將操作體驗描述清楚；內容明確、簡潔、直接、實用等關鍵就如同 UX 設計一樣。

5/分析 (Analysis)

分析這塊比較特別，主要是針對實證成果、絕對或相對結果、失敗的成果、改善措施等去做討論。通常沒有特別去鑽研或接觸，很難說明或是解釋，我個人在這方面也極度不熟。

設計師觀點 v.s. 使用者觀點

UX 設計師的觀點最主要有兩點：

  1. 設計師想要對使用這不重要的東西。
  2. 設計師知道對使用者不重要的東西。

在講整個 UX 中，最常被廣泛提到的應該是「同理心」。當人們在真正瞭解某個問題時，情感上會逐漸讓你覺得這也是你的問題；這時候你已經與使用者產生共鳴，因為同理心。

UX 核心：針對知道比你少的人們做設計。

那使用者的觀點又是什麼呢？

使用者觀點大概可以歸納出 3 個 WHAT:

1/「這是什麼？」

當使用者準備開始進入你設計的旅程，卻對行李內的攜帶物毫無頭緒，這樣的旅程大概會非常驚險。例如你設計註冊表單，用了顯眼的配色、精美的 icon 並不使用任何文字來敘述，為了不要破壞這個按鈕的美感；結果換來了使用者的疑惑，而沒人敢隨意點擊。喔，真是太糟了。

直接告訴他們、並盡可能使用簡潔有力的文字說明給使用者知道。

2/「有什麼利益？」

隨便點入一間商品服務網站，通常都會有精美的介紹來讓人知道「我的產品能帶給你甚麼樣的利益」；又或是當你要準備購買商品時，把關鍵字丟到 Google、PTT 等，跑出了相關的使用心得、開箱文。甚至當使用者造訪你的網頁時，就明確的打著「免費試用」。

以上這些都是能讓使用者知道「他們能得到甚麼利益」，除了牽涉到使用者的動機，還有誘因等其他元素，讓使用者知道他們能得到的利益，並促使他們繼續使用。

3/「我要做什麼？」

好了，基本上解完上面兩個疑惑，你已經釣到使用者了！太好了，大魚上鉤！

當使用者理解狀況後給予「下一步」讓使用者動作，可能是單純的「如何註冊？」，也可能是較複雜的「如何開始？」，藉由這個方式能夠由你來決定或釐清使用者的需求，並告知他們如何得到。

解法 v.s. 想法

UX 設計師不像其他視覺呈現上明確的設計師，能產出令人喜愛、藝術性的結果。當然也是會有這類產出（例如 prototype），但 UX 主要專注於創造分析、解決問題。

問題的解決方案是指對其他人有意義的想法，假設今天一個想法只解決了個人的問題、對其他使用者意義不大，那麼這只是滿足個人需求。

「那如果你的設計錯了呢？」

解決方案可以是錯誤的，就跟很糟的操作體驗一樣，去證明它是錯的並從中學習。

當然，每個解決方案不一定都全適用，也不見得適用 A 就適用 B。

使用者目標(動機) + 商業目標(動機) = 綜合目標

使用者有各種動機來使用你的產品，而身為設計師的你也為了他們設計了一套優質的體驗，太好了！使用者熱愛你的設計。

然而公司的收益關係了你的薪水，如果沒有這些商業目標，你可能會丟了飯碗。喔不！這真是太糟糕了。

因此身為 UX 設計師必須要妥善統合兩者目標，並別搞砸了。

現今很多免費產品都讓你能當「免費仔」，有些給的大方讓你所有功能都能用、有些則會限縮，或是有的靠其他方式從中收益。其中最常見的莫過於廣告，對！就是說你，當你正享受某件事物時突然跳出令人負面心情的搞事仔。

Facebook 每滑一段文章就會安插一個廣告、YouTube 每隔一段時間就會跳一段廣告，這算是將兩者的目標統合後取得一個平衡的實例。假設你今天看著一段很ㄎㄧㄤ的影片但每 30 秒就跳一段不用太長時間的廣告，我保證你馬上將你所學過的髒話都拿出來講一遍。

若像是電影院開場前在等候觀眾進場撥放一連串廣告，當準點一到就讓你能安心地欣賞整部電影，這也是一種統合兩者目標的好例子。

需求

藉由收集需求能夠瞭解不能夠做甚麼，以及必須做甚麼。

透過研究問題如「可以解決的問題、不可改變的事實、必須被涵蓋的技術」與其他專業人士討論所確認下來的限制和約束，進而保護你的設計免於錯誤。

當然，需求不是許願池，請篩選真正的需求。

「我也是使用者啊！」by 可能某位職位或薪水比你高的上級

當某人提出需求時，請務必繼續問他原因，如果答案關乎其他人的意見或期望，那這是有理的需求；若對方的回答沒有充分的解釋，這樣只不過是個人的期望罷了。

總結

以上的內容大概是我整理過後覺得在正式開始前需要先瞭解的，可能看完會覺得黑人問號，甚至覺得跟網路上其他前輩、大大寫的比起來挺難懂的，只能說我的文筆還不夠好來做初步介紹。

UX 設計師的工作聽起來像是中間溝通人，因此建立共識這件事情非常重要。在著手設計前必須有充分的理由支持你的論點、去證明你是對的，跟對方解釋他們不知道的重要想法，而不是空談。

在後續文章會開始盡量加入一些實例，以及個人經驗來輔助，盡可能讓文章能讀起來比較生動，也讓人能比較易懂。關於這部分會再加強，也歡迎給予賜正。

以上，我們下次見，啾~
