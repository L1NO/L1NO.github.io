一週年紀念🎉

設計鳥生活滿一歲啦！

Ossian Lin Published on Sep 2020

前言

在寫這篇之前，回頭想想：雖然過去一年幾乎是「每月壓底線、只有產一篇」的鳥樣子，但每個月一篇的堅持下，居然就這樣產出 12 篇文章。

（迷之音：你確定真的是 12 篇？

今天這篇除了慶祝滿一年外，主要會來聊聊過去一年撰寫文章的歷程，以及第二年新展望。

契機

以前其實就有寫過部落格、網誌的經驗，起初的目標都是一樣的：將筆記數位化。可能會有人覺得：「啊你就用什麼筆記軟體啊，幹嘛寫成文章？」如果只寫給自己看得懂，但當分享給他人時卻無法簡單理解，那這樣其實挺可惜的。

然而持續找東西寫實在不簡單，畢竟是要經過整理後，用易懂的口吻來編寫，所以以前常常寫一篇文章剛開始可能很投入，但只要忙碌一下再回頭可能就亂了思緒；這也是為什麼以前的文章很少搬過來寫的原因之一。

隨著新工作的開始，看了不少設計前輩的文章，想寫網誌的念頭又冒了出來；而在第一次聽 Akane 老師演講最後 Q&A 的時候，老師也推薦多寫部落格、網誌，因為這可以作為一種學習歷程、即便寫的可能不好。這也讓我回想起以前碩班實驗室開會時，博班學長那塞滿資料的投影片，讓人都覺得學長每次都能從裡面翻出東西報告。

在這樣的推力下，於是在去年這個時候，設計鳥生活誕生了！

起手式

既然都決定要寫下去了，那第一篇文章該寫些什麼？

嗯，當時真的是很難找題材來寫。最主要是初入社會沒什麼能東西，於是就挑了應該已經很多人寫到爛的 Tinder 來當作第一次嘗試。

起初的想法很簡單：找個 app 實際操作、分析內容，最後就能寫成文章。然而實際上光是操作流程架構的分析就花了許久時間，何況還要 match 到人然後嘗試聊天，而且還不知道花了時間聊天的內容是否符合。因此一連串的摸索，以及沒事先規劃好的去使用，最後不但花上近半年的時間外，還產出不太像 UX 分析的文章。

雖然說真的寫得不太好，但也算是真的跨出第一步，同時建立了個人的分析架構 N.T.U.S.T (kNow, Try, Use, Study, Total)，呃，可能有點牽強又爛梗，未來可能會再修改，應該。在寫文章的同時，其實也是有將剛看完的《UX從新手開始：使用者體驗的100堂必修課》這本書上學到的套進來，稱不上專業至少也現學現賣、順便複習。同時也更深入去了解「卡片式設計」這個部分，也促成後來寫了一篇介紹卡片式設計的文章。

不過現在回頭看當初想的概念其實還挺不錯的，只是內容上需要更專業跟深入，不然寫完實際上是真的挺廢的。

固定生產

有了第一篇的基本架構，接下來就能有系統的寫文章了…吧？

起初是這樣想的：「喔好，我也剛看完新手入門書了，搭配一些文章、找個 app 做測試，然後就來寫點心得吧！」當然有了第一篇文章的羞恥感，總是對第二篇會有點動力想要寫好、更專業，這樣才是進步啊！我們從小不都是這樣被教育「企鵝不捨」「好還要更好」之類的嗎？(企鵝：干我P事

加上當時剛做完一項活動用的 app 產品，超想把只有兩個人負責的整個開發過程跟背後秘辛都寫出來分享，甚至還可以接著去做很難得能做到的數據分析...哇，光用想的就至少有題目跟內容可以寫一段時間了！

組長：「诶你接下來要幫忙寫網頁前端喔~」

我是不知道組長還是上層哪來的勇氣，讓我這個 coding 菜鳥去負責一個幾個月後要上架的接單平台網頁前端…

「不我應該去嘗試！身為一位 UX 設計師未來也是要能徒手寫網頁的！」

對我「一開始」也是這麼認真向上，而且在稍微短暫的瞭解當今被常用來寫網站的架構後，選了看起來最厲害的 Angular 起手。此時的我隱約聽到以前朋友跟我說的一句話：

「你選了一條最艱難的道路呢~」

先撇除 Angular 本身難度，光是要補 C 語言、JAVA...等，就花了不少時間，而且這還不是最困難的部分，這也是讓我體會到甚麼是「探索與開發」這兩個階段的難忘經驗—「探索」也是我們負責，喔「我們」是指負責專案的兩個人，total、兩個人，again。

這段看起來很想寫抱怨，對就是抱怨。但也因為這大概半年的摸索網頁前端開發，讓我的 Html 跟 CSS 又更上一層，也這樣充其量寫了兩篇 Angular 新手教學。想寫這種文章的原因是因為網路上看到的幾篇教學都不太完整，會有一種似懂非懂的感覺，我後來發現原因就在於這些文章沒辦法讓人有手把手教學的感覺，至於你說為啥只有兩篇，因為我跟 G 胖一樣數不到 3 啦！

新展望與挑戰

我起初以為整個 2020 我都負責寫那個網頁前端案子就好，不過期中交貨的成果慘不忍睹，上頭大概也知道不能再讓我破壞下去…

然後我就被調去行政業務了。

說實在這樣的調動個人還挺喜歡的，首先可以脫離「RD 不 RD」的苦難，其次是經過一年的學習跟聽過數場講座，還上過課程、工作坊，我也覺得是時候開始更詳細的做 UX 設計這部份。即便工作內容沒有全職在 UX，還是有辦法以其他著點來做練習。

也因此第一篇閱讀心得、「評價系統」等文章也總算正式產出，讓整個網誌看起來真的比較像在寫 UX 設計相關的。即便行政業務也沒輕鬆到哪邊，至少可以更多心思在 UX 個人學習上、補回一些想寫的文章，同時有空間去做 profolio 為未來做準備。

目前規劃是以 2–3 個月來對一個 app 或是服務上做專一痛點的 redesign。相信應該有不少人有聽過、做過 redesign，甚至 Daily UI 這類挑戰。之前我也嘗試過，但有時候那考題真的是完全沒概念而作罷。後來看了一些文章也有點出我的困難，以及解決方式，藉由這些概念我想從中找出適合自己的方式來做 redesign 以及準備 profolio。

至於 UX 文章的部分，我想應該還是每個月維持至少一篇來做撰寫，算是對自我要求，不然這樣最後一定又會荒廢掉。看看 11 月的遊戲陣容！

後記

寫了這麼多，其實也還不知道接下來會怎麼發展呢～

即便現在待在行政業務這邊，但目前待的位子也是臨時被調派來的，能不能待到明年契約結束也都不知道，甚至哪時候這個組要被拆散…每天就跟抽牌一樣都是未知數呢！

不過，至少過去一年是腳踏實地的去寫每篇文章，而且不光是文章內容，在撰寫期間也都會再去看其他資料，間接地又學到更多，或是更深入研究。

User Experience 確實要學的非常廣，而真正執行的卻又沒幾個人做得到，在過去一年 RD 團隊時幫忙做的 3 個專案，甚至去看其他人做的專案，總會有「你確定要這樣做下去？」的想法，最可怕的是當你跟對方聊起來他們可能也沒頭緒，這樣一路錯下去還能不沉船…

以上，我們下次見，啾~
